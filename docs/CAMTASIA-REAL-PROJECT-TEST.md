# 用户实际 Camtasia 工程导入测试

测试日期：2026-10-13，TronCut 0.2.0 Windows 打包程序。

## 结论

目前无法完整导入这个工程。工程 JSON 可以解析，应用没有前端运行错误，但仅转换了背景音乐。录屏与背景未进入时间线，不能作为该工程的有效剪辑版本。

## 实际工程

用户提供的 `.tscproj` 路径实际为工程目录，测试读取目录中的同名 JSON 文件。精确私人路径和工程内容只保存在本机已被 Git 排除的 `test-output/` 中，不随公开仓库发布。

源工程 JSON 为 10.0 格式，1920×1080 / 30 fps，4 条轨道、5 个时间线片段，末尾 68.2 秒。素材库引用 6 个文件：3 个 TREC、1 个 MP3、2 个 tscshadervid。源工程没有独立 Callout 文本片段或嵌套媒体组，字幕属性已启用但未发现独立字幕片段；本样本不能验收这些兼容能力。

## 失败原因与解码诊断

当前导入器按扩展名排除 TREC 和 tscshadervid，因此 3 个 ScreenVMFile 与背景 VMFile 都被跳过。报告已显示这些素材与片段不支持。

三个 TREC 均可被随程序的 FFprobe 识别为 MOV/MP4 容器、TSCC2 视频：分别为 2560×1600 / 101.4 秒、2559×1522 / 103.9 秒、2559×1522 / 74.466667 秒。第一段在 2 秒处通过 FFmpeg 真实解码得到 PNG。额外通过打包应用现有媒体协议测试第一段原始 TREC，原生 HTML video 返回 MediaError code 4，未能直接预览。故支持这类文件需要导入时解码/转码或兼容预览路径，单纯放开扩展名不足以完成支持。

该测试没有解析 TREC 的专有鼠标轨迹、指针图片或其他元数据，也没有尝试还原 tscshadervid 背景。不能将视频帧可解码等同于 TREC 完整支持。

## 证据与原文件保护

所有输出位于 `test-output/camtasia-import/run-1791876337080/`：

- `summary.json`：源工程统计、转换结果与缺失报告。
- `desktop-result.json`：实际打包程序 UI 检查与原始 TREC 预览结果。
- `desktop-import-report.png` / `desktop-imported.png`：导入报告与仅剩音乐的时间线截图。
- `trec-decoded-frame.png`：FFmpeg 从原始录屏解码得到的图像。
- `converted-debug.json`：用于诊断的转换对象，含绝对素材路径，不作为可迁移工程交付。

源工程测试前后 SHA256 一致，精确校验值保存在本机测试结果中。未保存、重写或转码覆盖原目录中的任何文件；UI 测试数据和解码图像均写入本工作目录。

## 复现

先运行 `node scripts/test-camtasia-import.mjs <实际工程文件>`，再运行 `node scripts/test-camtasia-desktop.mjs <实际工程文件>`。后者启动 release/win-unpacked 中的程序，仅在该测试进程中替换文件选择对话框，测试后关闭程序。以上复现脚本不修改正式导入逻辑。
