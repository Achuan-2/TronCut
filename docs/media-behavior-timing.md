# 媒体行为进入时长的测量与校准

参考为 `references/camtasia/媒体行为动画照搬/媒体行为动画照搬.mp4` 及同目录 `.tscproj` 项目。原视频 1920×1080、30 fps、1680 帧，共 56 秒。项目画布为 3840×2160，`editRate = 705600000`。参考素材和项目只读，不参与应用运行。

## 如何计算

项目时间先按 `秒 = 时间值 / editRate` 换算。例如淡入的 `suggestedDurationPerCharacter = 1317928960`，换算为 `1.867813 s`。但这个字段是建议阶段长度，不能直接当作可见运动结束时间：铰链对应值为 `4.576142 s`，视频中约 `1.13 s` 就已经稳定。

因此再逐帧解码视频，按每段片头计算相对帧号。弹入至内爆分别从 0、5、10、15、20、25、30 秒开始；35 秒为无行为对照；显示、切换、滑入从 40、45、50 秒开始。以无行为片段第 36 秒的图像为各视频自身的稳定基准，在 480×270 分析尺寸下提取绿色通道亮度，忽略不超过 4/255 的黑底噪声，计算总亮度、亮度重心及形状差异。

某帧同时满足以下条件，视为“接近到位”：总亮度与基准相差不超过 5%；重心两个方向均相差不超过 2 分析像素，另加 0.125 像素量化容差；对齐重心、归一总亮度后的形状 L1 误差不超过 8%。量化容差用于避免 YUV420 编码让理论上 2 像素的位移变成 2.01 像素。总亮度同时受透明度和投影面积影响，不能独立解释为透明度。

“首次到位”是发生初始运动后第一次满足条件；“稳定”要求从该帧起连续 15 帧（0.5 秒）均满足条件，用来排除弹簧首次经过终点后继续回摆的情况。时间计算为 `片内帧号 / 30`，帧号从 0 开始。这个结果是带明确阈值的视觉稳定估计，不是 Camtasia 内部阶段终点。

## 本次实现

此前十个预设的阶段长度被统一缩到 0.3–0.5 秒，缓出还会使可见动作提前结束。本次分别设置进入时钟，期间和出场继续保留已有搭配。增长、铰链恢复参考阻尼 5，切换使用参考阻尼 7，弹簧刚度仍为 50；`springDuration` 分别为 2、1、1.8 秒，结合各自阶段长度校准回弹后的可见稳定时间。它是弹簧模拟时钟，不等于阶段播放长度。

淡入使用线性透明度。显示将两个通道分开：位置继续四次方缓出，透明度线性增长。设 `p = t / duration`，则进入透明度为 `p`，剩余位移比例为 `(1-p)^4`；半程时透明度为 50%，位移已经完成 93.75%。四方向选择和按素材尺寸计算的位移继续有效，预览和导出使用同一规则。

默认值用于新增行为和“更多 → 重置行为”；已保存项目、自定义预设里的阶段长度与弹簧时钟保留。短片段仍按比例压缩进出阶段，五秒片段保留至少两秒展示时间。

## 复现

在项目根目录运行，需要本地参考文件和 bundled FFmpeg；普通测试和构建不依赖参考文件。

```powershell
node scripts/measure-media-behavior-timing.mjs
node scripts/compare-media-behavior-timing.mjs
node scripts/measure-media-behavior-timing.mjs test-output/media-timing-comparison-<timestamp>/troncut.mp4
```

测量脚本输出完整的 `measurements.json`（源视频信息、阈值、逐帧数据、结果）及 `reference-contact.png`。解码使用 `fps_mode=passthrough`，避免自动补帧改变片内帧号，并核对帧率与总帧数。对照生成脚本沿用参考素材的位置、尺寸和片段边界，逐段真实导出；关闭期间与出场以单独测进入，保留各段可编辑 `.troncut`。合并时按帧重置时间戳并移除声音，避免音频包补齐导致后续片段偏移。

本次参考测量为 `test-output/media-behavior-timing-1792511244430/measurements.json`；新版对照视频为 `test-output/media-timing-comparison-1792510904009/troncut.mp4`，对应测量为 `test-output/media-behavior-timing-1792511244444/measurements.json`。这些是本地生成的验证产物，不提交进版本库。
